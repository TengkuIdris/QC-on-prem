# なぜなぜ分析AIエージェントAPI 要件定義書

## 概要
ユーザーの入力した問題、原因、及び観測情報に対してなぜなぜ分析を実施し、真因を特定するAIエージェントAPIを大規模言語モデル (LLM) をベースに構築する。本書では、PoCの成功を受けて本番実装するためのエージェントAPIの要件を定義する。

## 目的・背景
製造業や品質管理などの分野では、問題が発生した際に根本原因（真因）を特定することが重要である。「なぜなぜ分析」は問題に対して繰り返し「なぜ」と問いかけることで真因に迫る手法だが、分析の質は実施者の経験や知識に大きく依存する。本システムはLLMの知識を活用し、より客観的かつ効率的な「なぜなぜ分析」の実施を支援することを目的とする。

PoCにより基本的な機能の有効性が確認されたため、本番環境での実装を行う。バックエンド機能はフロントエンド側の開発組織に移管されることになり、本プロジェクトではエージェントAPIのみを開発する。

## システム概要
本システムは、AIエージェントAPIとして実装され、フロントエンド開発組織が実装するバックエンドシステムから呼び出される。主な処理フローは以下の通り：

1. バックエンドシステムからエージェントAPIに問題情報が送信される
2. Cloud Run上で動作するLangGraphエージェントが分析を実行（Vertex AI Gemini APIを利用）
3. エージェントAPIは「なぜ」の連鎖分析を実行し、必要に応じて対話内容をストリーミングで返す
4. 分析結果や対話履歴はCloud SQL PostgreSQLに永続化され、バックエンドシステムからアクセス可能

エージェントの状態と履歴管理はLangGraphのPostgreSQLチェックポインターを使用して実装し、処理の継続性を確保する。

## 機能要件

本エージェントAPIは以下の主要機能を提供する。各機能は【必須】【重要】【あると便利】の優先度分類を持つ。

### エージェントAPI機能

本 API は、Cloud Run 上で動作する LangGraph エージェントを直接実行し、リアルタイムな対話と分析結果のストリーミングを実現する。

#### REST/ストリーミングエンドポイント 【必須】
> **ベース URL**: `/v1` （以降のパスはこのベースに続く）

- **分析スレッド初期化 API** (`POST /v1/threads`) 【必須】
  - 新規なぜなぜ分析スレッドを初期化するエンドポイント
  - 入力：問題情報（ProblemInput構造体、言語設定を含む） (備考: 新規作成時はスレッド識別子は不要。パスやレスポンスで新しいスレッドIDが通知される)
  - 出力：スレッドID、作成日時

- **エージェント実行ストリーミング API** (`POST /v1/threads/{thread_id}/stream`) 【必須】
  - LangGraphエージェントの処理状況をリアルタイムでストリーミング
  - 入力：スレッド識別子、ユーザーレスポンス（対話の場合）
  - 出力（ストリーミング）：
    - イベントタイプ (イベントが発生したエージェントのアクション)
    - 処理状態 (エージェントの思考プロセス、現在の分析状態など)
    - ユーザーへの質問 (エージェントがユーザーに情報要求をした場合)

- **分析状態取得 API** (`GET /v1/threads/{thread_id}`) 【必須】
  - 現在の分析状態を取得するエンドポイント
  - 入力：スレッド識別子
  - 出力：
    - 現在の分析状態
    - 完了済みの場合は真因候補リストと確信度情報
    - ユーザーとの対話履歴

### なぜなぜ分析エンジン機能

Cloud Run上で動作するLangGraphベースのなぜなぜ分析エージェント。

#### 分析エンジンコア機能 【必須】

- **初期分析機能** 【必須】
  - 入力情報に基づく初期「なぜ」の提案（最大3項目程度）
  - 業界特有の知識と一般的知識を活用した分析

- **多段階分析プロセス** 【必須】
  - 最大5段階の「なぜ」の連鎖生成
  - 各段階での複数の可能性提示
  - 段階ごとの進行状況管理

- **確信度評価** 【重要】
  - 0～100%の確信度表示
  - 確信度に基づく優先順位付け

#### インタラクティブ対話機能 【必須】

- **情報要求機能** 【必須】
  - 分析に必要な情報の不足検出
  - 具体的な質問の自動生成

- **対話継続機能** 【必須】
  - ユーザー入力に基づく分析の継続
  - コンテキスト維持と会話履歴の参照

- **エージェントの思考プロセスの出力** 【必須】
  - エージェントの思考プロセスを出力する
  - ユーザーに分析が進行していることを示す

#### 状態管理機能 【必須】

- **チェックポイント管理** 【必須】
  - LangGraphの状態を保存するチェックポイント機能
  - 状態をデータベースに永続化する

- **再入力サポート機能** 【必須】
  - 直近のユーザー入力要求状態まで迷る自動復元
  - ユーザーの入力修正を受けて分析継続

### モニタリング・ロギング機能

エージェントAPIの運用と監視に関する機能。

#### エージェント監視 【重要】

- **エージェント実行トレース** 【重要】
  - 分析プロセスの詳細な実行トレース情報を記録・追跡可能にする

- **利用状況監視** 【重要】
  - API呼び出しのパフォーマンスメトリクス取得
  - LLMトークン使用量の計測


## 非機能要件

### 性能要件

- **レスポンス時間**:
  - API呼び出しの応答時間: 1秒以内
  - LLM処理を含む分析ステップ: 平均30秒以内、最大60秒以内
  - ストリーミングレスポンス: 初回レスポンスまで5秒以内
- **処理能力**:
  - 最大同時接続数: 初期100ユーザー、将来的に5,000ユーザーまでスケール可能
  - 1日あたりの最大分析スレッド数: 10,000スレッド
  - 月間アクティブユーザー: 10,000ユーザー

### スケーラビリティ要件

- **水平スケーリング**:
  - API層はCloud Runを使用し、トラフィックに応じて自動スケーリング
  - 負荷分散はCloud Load Balancingで実現
- **垂直スケーリング**:
  - LLM処理やデータベースリソースの動的調整
  - リソース使用状況に応じた自動スケーリング

### 信頼性要件

- **可用性**: 99.9%以上のサービス稼働率（月間ダウンタイム43分以下）
- **障害復旧**:
  - RPO (Recovery Point Objective): 5分以内
  - RTO (Recovery Time Objective): 15分以内
- **データバックアップ**: 日次バックアップと30日間の保持期間

### セキュリティ要件

- **通信の暗号化**:
  - すべてのAPI通信はTLS 1.3以上による暗号化
  - クラウド間通信は暗号化されたVPCピアリングまたはプライベート接続
- **データの暗号化**:
  - 保存データの暗号化（保存時暗号化）
  - 機密データの厳格なアクセス制御
- **認証・認可**:
  - APIキーおよびJWTトークンベースの認証
  - IPアドレス制限によるアクセス制御
  - API呼び出し元の認証（APIキーまたはJWT）。ユーザーレベルの認可およびテナント分離は、API呼び出し元であるバックエンドシステムの責任範囲とする。
- **監査ログ**:
  - すべてのAPIアクセスと管理操作の監査ログ記録
  - 不正アクセス検知のためのログ分析

### コンプライアンス要件

- **データ保護規制**:
  - GDPR、CCPA準拠のデータ処理と保存
  - データ処理に関する同意管理
- **業界標準**:
  - 製造業界特有のコンプライアンス要件への対応
  - ISO 27001セキュリティ規格への準拠

### 運用・保守要件

- **モニタリング**:
  - Google Cloud Monitoring によるリアルタイム監視
  - カスタムメトリクスとアラート設定
- **ログ管理**:
  - Cloud Logging によるログの集中管理
  - ログレベルの動的調整（DEBUG, INFO, WARN, ERROR, CRITICAL）
- **障害検知**:
  - 異常検知とアラート通知
  - エスカレーションフロー定義

## 技術要件

本エージェントAPIは、Google Cloud Platform 上で実装され、バックエンドシステムから呼び出される。技術スタックは以下の通り。

### エージェントAPI基盤

| 技術要素        | 詳細                    | 備考                          |
| :-------------- | :---------------------- | :-------------------------- |
| サービスタイプ  | REST API + ストリーミング | Server-Sent Events (SSE) によるストリーミングレスポンス対応 (FastAPI非同期ジェネレータを使用)  |
| 開発言語        | Python                  | 型ヒントサポート (すべて非同期実装)      |
| APIフレームワーク | FastAPI                 | OpenAPI仕様自動生成 (非同期実装) |
| コンテナ化      | Cloud Run 対応コンテナ  | サーバーレス実行環境               |

### エージェントコア技術

| 技術要素               | 詳細                                     | 備考                           |
| :-------------------- | :-------------------------------------- | :---------------------------- |
| 大規模言語モデル         | Google Vertex AI Gemini                 | 高性能な多言語マルチモーダルLLM    |
| エージェントフレームワーク | LangGraph                               | 状態管理、グラフベースの実行フロー  |
| エージェント実行環境      | Cloud Run                               | コンテナベースのサーバーレス環境     |
| LLMアクセス方法          | Vertex AI SDK for Python               | Gemini APIへのアクセス  |
| 補助ライブラリ           | LangChain                               | ツール統合、プロンプト管理        |
| チェックポイント管理      | `langgraph-checkpoint-postgres`         | PostgreSQL による状態の永続化と復元               |

### データ保存・状態管理

| 技術要素   | 詳細                    | 備考                              |
| :--------- | :-------------------- | :------------------------------- |
| データベース | Cloud SQL (PostgreSQL) | 状態管理用データベース               |
| 状態管理   | AsyncPostgresSaver     | 非同期PostgreSQLチェックポインター  |
| 接続管理   | langchain-google-cloud-sql-pg | Cloud SQL統合接続プール管理  |
| 履歴管理   | JSONB形式             | 対話履歴と分析プロセスの構造化保存    |

### 運用・監視基盤

| 技術要素   | 詳細                         | 備考                       |
| :--------- | :--------------------------- | :----------------------- |
| トレーシング | OpenTelemetry, Cloud Trace   | エージェント処理の可視化     |
| ロギング   | Cloud Logging                | 集中型ログ管理               |
| メトリクス | Cloud Monitoring             | パフォーマンスと利用状況の監視  |
| 認証       | IAM, APIキー                 | APIアクセス制御             |

### デプロイメント環境

| 技術要素         | 詳細               | 備考                          |
| :--------------- | :----------------- | :------------------------- |

| CI/CD            | Cloud Build        | テスト、ビルド、デプロイの自動化 |
| テスト環境       | pytest             | 単体テスト、統合テスト           |
